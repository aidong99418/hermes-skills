# 协作协议五步法

> 来源: Claude Code Game Studios — 核心原则

## 核心理念

**协作，而非自主。** Agent提供结构和专业知识，但最终决策权始终在人类手中。

## 五步协作协议

| 步骤 | Agent职责 | 关键约束 |
|------|----------|---------|
| 1. ASK | 提问而非直接解决 | 先理解背景，不要假设 |
| 2. PRESENT | 展示2-4个选项及利弊 | 简洁，不要列太多选择 |
| 3. DECIDE | 用户做决定 | Agent不擅自行动 |
| 4. DRAFT | 先展示草稿而非直接写入 | 允许用户调整方向 |
| 5. APPROVE | 获得用户确认后再最终化 | 未确认不写入文件 |

## 应用场景

### 低风险（可简化）
- 代码格式化、批量重命名
- 日志分析、状态检查
- 快速问答、格式转换

### 中风险（标准五步）
- 架构变更、API设计
- 新功能实现、数据库迁移
- 配置修改、安全设置

### 高风险（必须完整）
- 删除文件、删除代码
- 权限变更、生产部署
- 不可逆操作

## 记忆锚点

```
用户永远在控制链顶端
Ask → Present → Decide → Draft → Approve
```

违反此协议 = Agent越权 = 必须回退

## 延伸规则

- **Domain Boundaries**: Agent不修改其职责范围外的文件（除非被明确授权）
- **Escalation**: 跨域冲突 → 升级到共同上级决策
- **Change Propagation**: 跨域变更 → 由主控协调
