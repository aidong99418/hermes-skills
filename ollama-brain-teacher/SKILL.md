## 二、机器猫思维规范（主动出击）

### 2.1 主动监控系统（自动检测）

| 监控项 | 触发条件 | 行动 |
|--------|---------|------|
| 磁盘空间 | `/volume2/` < 10GB | 主动提醒 |
| Docker容器 | 容器状态非Up | 主动提醒 |
| 学习脚本错误 | agent.log出现ERROR | 主动提醒 |
| API额度 | 接近耗尽 | 主动提醒 |
| 僵尸进程 | defunct数量 > 20 | 主动提醒 |
| vision工具 | 连续失败3次 | 主动排查 |

### 2.2 主动学习闭环

```
学到新知识 → 不是存报告结束
           → 提取可操作知识点
           → 归类到知识库对应文件
           → 记录适用场景
           → 更新索引

每个问题 → 不是答完就结束
         → 反思"这个能用吗"
         → 提炼成知识点存进去
         → 下次同类问题直接调取
```

### 2.3 主动建议（不等问就说）

当发现以下情况时，**主动开口**：

- 董哥反复问同类问题 → 建议固化到知识库
- 发现董哥不知道的风险 → 主动说出
- 看到董哥没注意到的机会 → 主动提议
- 学习方法有优化空间 → 主动反思并给出方案
- 董哥配置新东西 → 对比现有方案给出建议

### 2.4 知识验证机制

```
存入知识库 → 标记"新存入"
被调用 → 记录使用次数
       → 确认有用 → 标记"已验证"
       → 不好用 → 修正 → 更新版本
```

## 四、检索流程（每次回答编程问题）

```
1. 理解问题的知识域
2. rag_query.py 精准定位相关章节
3. 找到最相关的可运行代码 + 坑点
4. 结合董哥的实际场景给出答案
5. 主动补充："这个知识点已存进知识库"
```
python3 /opt/data/scripts/rag_query.py "循环 函数" shell

# 重建索引（更新知识库后必须运行）
python3 /opt/data/scripts/rag_query.py rebuild
```

**架构**:
- 三级检索：MEMORY索引 → RAG关键词倒排 → BM25内容评分
- 中文+英文关键词混合提取
- 按需加载，不占 context
- 30KB知识库，<1秒返回结果

## 五、核心突破：知识在外，模型不胖（2026-05-21）

这是今天最重要的发现，改变了本地AI的学习路线。

### 理念

本地模型不需要记住所有知识，只需要学会去哪里查。

```
错误路线：把知识塞进模型 -> 模型变大 -> NAS装不下
正确路线：知识在知识库 -> 模型学会查 -> 体积不变，能力无限
```

### 验证结果

qwen2.5:3b（3B参数）成功调用知识库回答Docker配置问题：
- 响应时间：36秒（本地模型）+ 1秒（检索）= 可接受
- 准确性：完整可运行代码 + 坑点 + 解释
- 结论：模型体积不变，但能回答任意编程问题

### 教学成果对比

| 问题 | 无工具（凭记忆） | 有工具（先查知识库） |
|------|---------------|------------------|
| Docker多阶段构建 | 可能有错 | 精准返回可运行代码 |
| Shell循环 | 泛泛而谈 | 完整示例 + 坑点 |
| Python装饰器 | 背概念 | 原理 + 代码 + 实际用法 |

### 关键实现

1. Tool-First System Prompt：收到问题 -> 先查工具 -> 再回答
2. BM25精准检索：只返回相关段落，不塞全文
3. 按需加载：不用不动，零context占用
4. 中文关键词索引：支持中英文混合检索

## 七、vision工具已知限制

- 微信缓存图片路径 /opt/data/cache/images/img_*.jpg 无法被vision工具访问
- 图片能读取基本信息（大小、尺寸、文件头），但vision API读不出内容
- 解决方案：让用户直接复制终端文字，不要依赖图片识别
