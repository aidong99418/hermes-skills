# Zoom Out — 宏观视角技能

## 核心定位
当AI深入某个细节时，用户或系统主动触发"zoom-out"，让AI跳出细节，给出更高层次的抽象视角，用项目领域术语描述全貌。

## 触发条件

| 场景 | 触发信号 |
|------|---------|
| AI在某个函数/模块里绕不出来 | 代码细节过深，超出用户需求范围 |
| 用户问"这段代码是干啥的" | 需要理解模块在整体中的位置 |
| 遇到陌生代码区 | 不确定某段代码属于哪个子系统 |
| 架构讨论 | 需要整体视图而非局部实现 |

## 响应格式

```
## 当前模块：{模块名}

### 抽象层级上移
- 从 {当前层级} → {上一层级}

### 模块关系图
```
[模块A] ──调用──> [模块B]
   │
   └──共享──> [数据层]
```

### 领域术语映射
- {内部名称} = {领域术语}
- {内部名称} = {领域术语}

### 入口点
- 用户/外部 → {顶层模块}
- {顶层模块} → {中层模块} → {本模块}

### 调用链
{本模块} ← {中层模块} ← {顶层模块}
```

## 示例对话

**用户**：我不熟悉这部分代码，zoom-out一下

**AI**：
```
## 📍 当前模块：brain_thinker

### 抽象层级
- 从 **brain_thinker函数** → 上移到 **三层思考系统**

### 模块关系
```
[用户输入] → [brain_thinker] → [tier判断器]
                   │
                   ├── tier1 → 直接回答
                   ├── tier2 → 工具链推理
                   └── tier3 → 深度RAG搜索
```

### 关键术语
- `tier` = 思考深度等级（1=快/2=中/3=慢）
- `chain` = 推理步骤链
- `context` = 对话上下文窗口
```

## 使用场景

| 场景 | 效果 |
|------|------|
| 接手新项目代码 | 快速建立全局认知 |
| 调试复杂问题 | 看清调用链路定位根因 |
| Code Review | 从架构层评价而非逐行 |
| 需求讨论 | 用业务语言而非技术细节 |
| 知识传承 | 新人快速理解系统全貌 |

## 与其他技能配合

- **brain-thinker**：zoom-out是brain-thinker的外部触发指令
- **brain-retriever**：宏观视角后，用retriever深入特定知识节点
- **code-reviewer**：zoom-out → CodeReview，双视角切换

## 注意事项

1. **不要过度抽象**：保留足够的细节层次，至少3层
2. **用项目术语**：避免泛泛而谈，要用实际代码中的类名/函数名
3. **动态适应**：根据用户熟悉度调整抽象层次
4. **配合图示**：能用文字就画ASCII图，复杂时建议用架构图skill
